## 3. End-to-End Data Pipeline Mapping

### 3.1 Edge / Firmware → Payload Bytes

**File:** `firmware/src/main.cpp` (lines 16–53)

1. `readDistanceMm()` is stubbed to return `0x06D6` (1750 mm). Production must add ultrasonic trigger/echo timing.
2. `readBatteryVoltage()` is stubbed to `3.5f` V. Production must add ADC reading.
3. `buildPayload(uint16_t distance, float batteryVoltage)` packs:
   - `payload[0] = distance & 0xFF`
   - `payload[1] = (distance >> 8) & 0xFF` (little-endian)
   - `payload[2] = (uint8_t)(batteryVoltage * 10.0f)` (0.1 V resolution)
4. `sendLoRa(payload, 3)` is a `printf` stub. Production must call the ASR6601 LoRaWAN stack.
5. `enterDeepSleep(15 * 60)` is a busy-wait stub. Production must use STM32 stop/standby.

### 3.2 ChirpStack Payload Formatter (Edge Decoder)

**File:** `firmware/decoder.js` (lines 11–31)

```js
const distance = (bytes[1] << 8) | bytes[0];   // mm
const battery  = bytes[2] / 10.0;              // V
return { data: { waterDepth: distance, battery } };
```

The C++ little-endian packing and JS little-endian decoding are consistent. Note: the variable is named `waterDepth` in the decoder, but it actually represents the raw sensor distance (empty-to-water-surface). This naming will become confusing once the backend computes true water depth.

### 3.3 LNS Routing

**Files:** `chirpstack-docker/configuration/...`

- `chirpstack.toml` enables `eu868` and points MQTT integration to `tcp://mosquitto:1883/` (line 90). JSON output is enabled (`json=true`, line 91).
- `region_eu868.toml` configures the `eu868` gateway topic prefix and MQTT server.
- `chirpstack-gateway-bridge.toml` listens on UDP `0.0.0.0:1700` and publishes/subscribes on `eu868/gateway/{{ .GatewayID }}/event/...` and `.../command/...`.

The ChirpStack HTTP integration (not MQTT) is the path used by the current Node.js `ingest.js` route. Configuring the HTTP integration in the ChirpStack Application UI would point to `http://<host>:3000/api/v1/ingest/chirpstack`.

### 3.5 Engine & Database Persistence

**Health Score:** `src/lib/healthScore.js` (lines 3–32)
- `fillRatio = waterDepth / emptyDistanceMm`
- 30-min rise penalty
- Blockage/tamper penalties

**Predictive Engine:** `src/lib/predictiveEngine.js` (lines 46–102)
- Fetches latest `WeatherReading.rainfallRateMmHr` for the node's `subCounty`.
- Loads `CatchmentBasin` to get `surfaceCoefficients` and `catchmentAreaSqKm`.
- Computes `runoffQ` (m³/s) via Rational Method.
- Converts to `runoffInflowMmPerMin` using `drainCrossSectionAreaSqM`.
- Computes `rateOfRiseMmPerMin` from recent telemetry.
- Returns `predictedMinutesToOverflow` and `riskStatus` (`NORMAL`, `ELEVATED`, `CRITICAL_IMPENDING`).

**Anomaly Engine:** `src/lib/anomalyEngine.js` (lines 5–25)
- Returns `BLOCKAGE_SUSPECTED` when high rainfall, low flow, and low depth co-occur.

**Database writes:**
- `Telemetry.create(...)` (`src/models/Telemetry.js`, lines 3–16)
- `DrainNode.save()` status/lastSeen
- `MaintenanceTicket.create(...)` (`src/models/MaintenanceTicket.js`, lines 5–15) — `post('save')` triggers mock SMS.
